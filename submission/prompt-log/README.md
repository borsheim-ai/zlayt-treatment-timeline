# Reading guide

This folder is a near-verbatim record of how the project was built, and the quickest way in is `TOOLS.md` (which models, how the team was organized), then `transcripts/INDEX.md`. The prompts that matter most are the briefs at the top of each subagent transcript (the exact prompt that agent worked from) and `CONTRACT.md`, the operating contract the orchestrator was given. Chris's own conversation with the orchestrator and his inbox notes are omitted at his request; the master prompt (MASTER_PROMPT.md) is included. Every file in `transcripts/` is therefore a subagent: one file per spawned agent (worker, reviewer persona, or a one-off check), named `session-<id>-<agent id>-<label>.md`. To see supervision rather than generation, read one card end to end: pick a `T-###` from `board-activity.jsonl` (the append-only event log), find the worker transcript that built it, then `reviews/T-###-*.md` for what an independent reviewer found in a fresh context, and the later transcript where the finding was fixed. `decisions-and-lessons/` has the decisions the orchestrator made when reviews disagreed or budget forced a trade (`ORCHESTRATOR_DECISIONS.md`), the architecture decisions (`DECISIONS.md`), and every failure of the process with the harness change it caused (`LESSONS.md`); the lessons are the most candid part of the log.

The transcripts are exported by `tools/export_prompt_log.py` from the Claude Code JSONL files (driven by `evals/finalize_prompt_log.py`), and rendered as markdown with each model's thinking, tool calls and tool results in order. They are not summarized or tidied, but they are not byte-for-byte raw either: eight kinds of edit were made, listed here, and nothing else.

Nothing else was changed in the transcripts, `reviews/`, `decisions-and-lessons/` or `board-activity.jsonl` (the copies of `docs/CONTRACT.md` and the three memory files get edits 1 and 2 only). Edits 1 to 4, 7 and 8 apply to every file in this folder except `README.md`, `TOOLS.md` and `REDACTIONS.md`; the counts below are occurrences of each marker in the built folder, so they include any marker string that was already in a source document.

1. **Secret redaction**, marker `<redacted>` (740 occurrences in 137 files). Any string matching a `tools/check_secrets.py` pattern is replaced (for `ANTHROPIC_API_KEY=` only the value). The exporter masks `sk-ant-` keys and `ANTHROPIC_API_KEY=` values as it exports and `evals/finalize_prompt_log.py` replaces anything else the scanner matches. No key-shaped value remains in the folder, and values masked at export time were not inspected. `REDACTIONS.md` itemizes the finalize step's replacements by file and class, never by value.
2. **Private-network redaction**, marker `<redacted-private>` (1,360 occurrences in 162 files). Tailnet hostnames and labels, any mention of the tailnet suffix, Tailscale 100.64/10 addresses and the `100.x.` prefix, a work email address and its domain (one former-employer name in the bio in the `CONTRACT.md` copy is among them), and regex, backslash-escaped, quote-and-plus-split, one-character-wildcard and punctuation-gapped spellings of all of these (for example a pattern written with a backslash before each dot, a value cut into quoted pieces joined with `+` or into a tuple of quoted pieces, a regex with `*` or `?` between the name and the dot). A bare work-email domain counts as one of these. Names of Chris's computers and phone are replaced by `<device>` (240 occurrences in 39 files); the phone name is also replaced when it appears without its trailing number. The final check removes backslashes, quotes, `+` and whitespace from every file, folds case, allows up to 12 punctuation characters between the characters of each term, and confirms none of these terms remains.
3. **Personal and third-party redaction until Chris decides**, markers `<third-party name>` (40 occurrences in 13 files), `<personal file>` (264 occurrences in 26 files) and `<home-path>` (128 occurrences in 37 files). A third party's name is masked; the names of Chris's job-application folders and files, and of his call-prep files, are `<personal file>` (a folder name on its own too); paths under the home directory other than this repo, `~/.claude`, the nvm and Playwright caches and the Claude scratch folder are `<home-path>` (so other local project names and `-Users-arsis-<project>` temp folder names are masked). The local `/Users/<name>` prefix of this repo's own path is left as it is. Prose that merely mentions another project by name is not edited, except the one outside project covered by edit 7.
4. **Content from outside this repo omitted**, marker `<outside-repo file omitted>` (1,046 occurrences in 395 files). The tool result of any command or file read that touches a place under the home directory other than the paths allowed above, or whose result text itself names such a place, is replaced by this marker; the call itself stays. This removes file excerpts from Chris's other local projects (for example a sibling product repo) and directory listings of his job-search folders. If an agent repeated such content in its own reply or reasoning, that text is not edited.
5. **Images shown as `[image]`** (1,017 occurrences in 157 files). The agents and reviewers looked at screenshots; the export has no image data, so each image block is the literal text `[image]`.
6. **Four-backtick fences escaped** (103 occurrences in 18 files). Tool output is wrapped in a four-backtick fence; any four-backtick run inside it is rewritten to `` ` ` ` ` `` so the markdown stays valid. Non-text tool-result blocks are likewise shown as `[<type>]`, and the first line of each transcript says "Unedited except redactions and format changes listed in the README".
7. **Outside project name redacted until Chris decides**, marker `<outside project>` (584 occurrences in 127 files). The name of one other project of Chris's (the one the omitted excerpts in edit 4 came from) is replaced wherever it appears, in any letter case and in these forms: a path segment, a file-name slug, prose, a backslash-escaped spelling, a value cut into quoted pieces joined with `+` or spread over whitespace, a tuple or regex whose pieces are separated by punctuation (up to 12 characters), or one character replaced by a wildcard. A path that runs through the name (a folder named after it, its sub-folders and the file) is replaced whole by the one marker. Unicode (`\u`), percent and HTML-entity escapes are not decoded. This is a default, not a verdict: it stays on until Chris says whether the name may be shown, and `REDACT_OUTSIDE_PROJECT_NAME` in `evals/finalize_prompt_log.py` is the single switch for it (no entry in the local patterns file can mask the name when the switch is off). Where a path or file-name rule from edit 3 already covers the whole path, that rule's marker is used instead.
8. **Chris's own words omitted at his request**, markers `<Chris's message omitted>` (67 occurrences in 27 files) and `<Chris's inbox note omitted>` (17 occurrences in 2 files). Chris's own conversation with the orchestrator and his inbox notes are omitted: the two orchestrator session files (every session that carries his own user turns) are not in `transcripts/` or `INDEX.md`; in every other file a run of eight or more words copied verbatim from one of his messages is replaced by the first marker (runs that also occur in `MASTER_PROMPT.md` are kept, because he authorized that document); and the text of each board-inbox event in `board-activity.jsonl` is replaced by the second marker. Shorter quotations and paraphrases of his steering by the agents are not edited.

Tool results are otherwise at full length (no result was capped). The transcripts are a snapshot taken when this folder was built (the card that built it, T-187, is the last transcript), so a rebuild grows them slightly and counts can shift by a few.
