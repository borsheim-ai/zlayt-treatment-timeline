# T-149 UX review: multi-case overview and detail (Priya Raman lens)

Verdict: changes (0 blockers, 4 majors, 7 minors, 1 nit). Served from `git archive HEAD` (25f585c, which contains 1394661; `git merge-base --is-ancestor 1394661 HEAD` printed ancestor-ok; repo-root tree had 2,156 uncommitted changes, so I used the archive) on port 7931, fixture backend, ZLAYT_MODE=local, scratch DB. Seven cases: sample, lib01, lib02 (ingested only), lib03, lib06, lib09, a pasted copy of the sample with a 100-character name. Server stopped by PID 21516; port 7931 returns 000.

What works: the overview is scannable, filter and sort do what they say, keyboard open and return are good, 390 has no sideways scroll, dark mode reads well. What fails: the overview's "need review" call-out goes stale after the paralegal decides (it contradicts the progress bars in the same row), load and open errors are invisible, the detail block repeats three widgets already on the screen, and the green "Ready to export" chip sits beside "8 need review".

Scores (1-5): design quality 3, originality 3, craft 3, functionality 3. None is 2 or below.

Competitor comparison (from public product knowledge, not tested in this review; I did not open EvenUp, Supio, Filevine or Litify): Filevine and Litify case lists are sortable tables with one stage or status column, a next task or deadline, an owner and saved views, plus search. EvenUp and Supio lists lead with a single matter status such as in progress or ready for review. This prototype is stronger at showing HITL workload (decided/total per kind, reasons for a blocked export). It is weaker on one-status-per-row, search, sortable columns and a per-row next action. Rows are 120-156 px tall at 1440 (5 fully visible in 900 px), so it will not scale past about 20 cases without search.

Evidence files are under `artifacts/review-evidence/T-149-ux-*` (scripts `T-149-ux-setup.py`, `-walk1.py` to `-walk8.py`; screenshots named in the findings).
