## Findings

**F-1 (major). The first "Run the second check again" is still offered in four places on a held quote whose check already gave no answer; clicking it cannot clear the hold, and the server's own gate sentences still say "Run the second check again."** State S2 (record 1 re-picked and compared, judge unavailable, only blocker). I counted the visible `btn-rerun-judge` buttons: three with the rail open, plus one inside "How the AI was checked" (`r1.stdout.txt` "[S2] BADWORD hit tid=btn-rerun-judge" x3; `r3.stdout.txt` S2 panel text "Run the second check again for this item"). The sentences beside them: rail "What you need to do: The second AI check did not run on 1 item. Run it again; accepted items it never checked cannot go in the letter. ... Run the second check again, or write the summary in your own words."; "Ready to export?" step "1 accepted item has not had the second AI check, so the export is blocked. Run the second check again." (`co-gate-why`, `step-why`). Yet the row on the same screen had already said, before I compared, "The second check failed (the AI check was asked and gave no usable answer), so this item has not been double-checked" (`r1.stdout.txt` "S1 e1 row"). So the check was asked on this exact pair and gave no answer, and the screen then asks her to ask again first. I clicked it: `POST .../rejudge` returned `"rejudged":[],"still_unavailable":[{"item_id":"e1",...,"verdict":"unavailable"}]` (`r2.stdout.txt` "NET after rerun click"), and only after that click did all rerun buttons disappear and the text switch to "Write the summary in your own words" (`r2.stdout.txt` "AFTER RERUN"). D-058 names the way out as writing the summary herself; the handoff says a rerun stays "only until the server marks rerun_no_answer", which is a design choice, but it is the thing my round-2 finding and this brief said not to offer. The case-level API `next_action` also stays `{'code': 'RERUN_JUDGE', 'text': 'Run the second check again.'}` after the failed rerun (`r2.stdout.txt` "GATE after rerun"), so another client reading it would still send her back. Why it matters: she spends a click and a wait to learn what the row had told her, and a sentence still tells her the check will run if she asks. Fix: when the server's trace for the held item already shows the second check returned unavailable on the new pair (the state S1 text describes), show only "Write the summary" in the rail, the gate step, "Ready to export?" and the AI panel, and keep the rerun only for an item where no check has been asked on the current pair; have the server's gate headline and `next_action` for that item say "Write the summary in your own words" (a backend line, T-134). Acceptance test: e2e with the judge unavailable, record 1 re-picked and compared: no `btn-rerun-judge` is visible anywhere before any click; none of the rail, gate step, "Ready to export?" step and AI panel contains "Run the second check again"; `GET /trace` `export_gate.next_action.code` is not `RERUN_JUDGE` for that item; each place shows "Write the summary" and the click focuses record 1's textarea.

**F-2 (minor). Before I compare, "How the AI was checked" says all agreed while record 1's new pair has no check.** State S1 (quote re-picked, not yet compared): the panel headline reads "checked 19, all agreed with the draft" and the panel body "19 items checked by AI, 19 agreed, 0 unavailable" (`r3.stdout.txt` S1, "AI-CHECK AREA"). The row for record 1 says "The second check failed ... this item has not been double-checked." After I compare, the panel corrects itself to "18 checked, 18 agreed with the draft, 1 not checked, blocks export: 1". So the panel counts the verdict on the old quote for the pair that is now different. She reads "all agreed" and trusts it, one screen above the row that says otherwise. Fix: count an item whose quote was changed after its check as "not checked on the new quote" from the moment the quote changes. Acceptance test: after a quote re-pick with the judge unavailable, the panel headline contains "not checked" and "unavailable" is 1 before she compares.

**F-3 (minor). The headline still reads "Ready to export" while an edit is held out (round-1 F-3, declared left).** S1 case summary: "Case checks | 8/10 checks passed | 2 need you | Ready to export, 22 not reviewed" with the held edit counted in "4 items need review, including 1 edit to check" (`r1.stdout.txt` "[S1] case-summary#0", "S1 progress"). The gate does pass here and the edit is out of the letter, so this is a wording issue, not a wrong gate. It is the same item the handoff lists as "Left". Fix as in `reviews/T-136-paralegal.md` F-3: while an edit to check is open, do not use the bare "Ready to export"; say "Can export, 1 edit to check, 22 not reviewed". Acceptance test: with one edit to check open the case-summary headline does not match `^Ready to export` without the edit count.
